# 09 — Turn the Task You Hate Into a Button You Press

### Small, Safe, Compounding Automation

**Format:** 60 minutes · live or virtual · bring the task you resent most
**Series:** Nurse AI OS — General Practice Workshops
**Boundary:** Non-clinical. No patient care, no medical advice, no PHI, no hospital or clinical
workflow automation. Automate your own admin, your own business, your own week.

---

## The promise

> **Setup:** Everyone is talking about automating their work. Almost nobody in this room has
> actually automated one single thing, and it isn't for lack of trying.
>
> *(pause)*
>
> **Reveal:** It's because you've been looking for the big win. The whole game is one small task
> you do every week and resent every time — and it's the last place anyone looks.

**One sentence:** You will pick one recurring task, write it down properly for the first time in
your life, and turn it into a repeatable routine you can trust — because you'll have watched it
run beside you before you handed it anything.

---

## Who this is for

Freelancers and consultants drowning in the same admin every Friday. Small-business owners
doing the invoicing, the chasing, the summarising, the reformatting. Team leads producing the
same report from the same sources every month. Nurses running non-clinical operations — a
course, a side business, a committee, a newsletter. Anyone who has said "I could train someone
to do this" and never had anyone to train.

---

## Learning outcomes

By the end of this session, participants will be able to:

1. Audit their week for **frequency × friction** and select the correct first candidate — which
   is almost never the one they came in wanting to automate.
2. Apply the **four-part selection rule**: frequent · boring · low cost of being wrong ·
   clearly definable output. And name what fails it.
3. Write a **task spec** precise enough that a competent stranger could execute it without
   asking a question.
4. Define **refusal conditions** — what the routine must never do, and when it must stop and
   ask.
5. Run a routine in **shadow mode** beside their own manual work, and compare, before trusting
   it with anything.
6. Run the **compounding loop**: define the outcome · build it · run it on real work · measure
   what it took off your plate · feed the corrections back so the same mistake never returns.
7. Maintain a **never-automate list** and explain each entry.

## Run of show (60 minutes)

| Time | Segment | What happens |
| --- | --- | --- |
| 0–5 | **Open: the resentment audit** | Three tasks you do repeatedly and resent. How often. How long each time. Multiply it out to hours per year. The number is the motivation and it is always worse than people guessed. |
| 5–12 | **Teach: choosing correctly** | The four-part rule. Why the task you *most* want automated usually fails it — high stakes, poorly defined, or done once a quarter. *If you only do it monthly, don't automate it; just do it.* |
| 12–17 | **⏸ DEMO PAUSE 1 — A named routine running** | *See notes below.* |
| 17–28 | **Write the spec** | Purpose · trigger · inputs (and where they come from) · steps in order · exact output shape · what it must never do · who approves before anything leaves. Eleven minutes. The output-shape field is where most people discover they never actually decided. |
| 28–33 | **⏸ DEMO PAUSE 2 — Shadow mode** | *See notes below.* |
| 33–41 | **Teach: the compounding loop** | Define · build · ship it against real work · measure what came off your plate · improve by feeding corrections back. Why step four is the one everyone skips and the only one that tells you whether any of this worked. |
| 41–46 | **⏸ DEMO PAUSE 3 — Correcting once** | *See notes below.* |
| 46–55 | **Pairs: break each other's spec** | Swap specs. Your partner follows it *literally*, like a difficult new starter, and marks every ambiguity. Every "obviously" you wrote is a defect. Rewrite. |
| 55–60 | **Close** | Reflection, call to action, and the never-automate list. |

## Demo pause notes

**⏸ DEMO PAUSE 1 — A named routine running (≈5 min).**
Show one saved, named routine: a single instruction in, a structured, predictable result out.
Emphasise *named* and *structured*. A routine that produces something slightly different each
time is not a routine; it's a conversation with extra steps.

**⏸ DEMO PAUSE 2 — Shadow mode (≈5 min).**
Show the routine running alongside the same task done manually, and compare the two outputs
honestly, including where the routine was worse. This is the most important demo in the
workshop: trust is a thing you accumulate through evidence, not a setting you switch on.

**⏸ DEMO PAUSE 3 — Correcting once (≈5 min).**
Find an error, correct it once, and show the correction persisting into the next run. Then say
the line: the difference between a tool and a system is that a system only makes each mistake
one time.

---

## Practical takeaways (usable tonight)

- **The resentment audit** with hours-per-year attached to each item.
- **One completed task spec**, already broken and repaired by a partner.
- **The shadow-mode rule:** run it beside yourself for two weeks before you rely on it.
- **The five-step compounding loop** on a card.
- **A never-automate list** — anything where being wrong is expensive, anything that is really
  a relationship, anything you're automating because you're avoiding it.
- **A minutes-returned tracker**: one line a week, so you find out whether it worked.

---

## Closing reflection and call to action

> A system you can trust is not one that never fails. Everything fails.
>
> It's one that fails where you can see it, stops when it's unsure, and never surprises you in
> the same way twice. That is the entire standard, and it is a standard that comes from
> professions where the alternative was unthinkable.

**Call to action:** Ship one routine this week — the small, boring, weekly one, not the
impressive one. Run it in shadow mode for two weeks and write down the minutes it returns. If
it returns none, delete it without ceremony and pick a different task. That is not failure;
that is the loop working.
