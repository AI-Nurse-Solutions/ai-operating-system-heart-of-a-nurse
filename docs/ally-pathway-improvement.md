# Ally pathway — improvement and release handoff

Human release owner: **Robert Domondon**. Status: local prepublication candidate only.

## What changed

- Four canonical welcome/reflection/setup/stewardship pages, distinct ally copy and navy/teal/gold styling.
- Eight manual offline package sources and four public downloads. Personalized SOUL answers are downloaded separately, never embedded in the generic archive.
- A quiet secondary homepage section beside the physician welcome, without primary CTA or unrelated content changes.
- Four sitemap routes dated 2026-09-30; both workflow path-filter blocks and ally safety-scanner loop.
- Portable contracts and repeatable real-Chrome QA. See `ally-pathway-publication-review.md` for actual execution results and evidence paths.

## Four pillars: next improvements, not promised capabilities

## Issues found and addressed locally

- Cross-profession copy adaptation initially produced awkward phrases (e.g., treating allied health as an agent identity). These were replaced with ordinary-language welcome and licensed-professional boundaries; no physician credential implication remains.
- Downloaded certificate styling was aligned to navy/gold rather than the inherited green physician styling.
- Dark-header keyboard focus was given brighter gold separately from light-surface focus.
- Two QA harness assumptions, not product failures, were corrected: Playwright may invoke a returned function from `evaluate`, so print interception must return no function; a `file://` document reload is not an HTTP network request. The full browser suite was then rerun successfully.

## Before publication

1. Robert approves the invitation, business/manager boundaries, optional ceremony, appearance and commemorative-only certificate.
2. Parent performs independent review and runs required aggregate repository checks/CI. Focused local coverage is not a claim that the entire repository suite passed.
3. Recheck official hardware/provider/plan instructions and external links at release time. This build did not install Hermes or authenticate to Nous.
4. If authorized later, publish through the repository's established process and verify exact served routes/download bytes. Until then, do not push, create a PR, merge or deploy.
5. Only after live verification, decide whether to extend monitoring. Do not add a live baseline or schedule for an unpublished route.

## Deliberately unresolved, not hidden

No active community membership channel, affiliation, formal certification, clinical authorization, business-outcome evidence, enforced runtime governance or full data sovereignty is established. Full screen-reader/assistive-technology testing and real ordinary-user usability research remain future work. The sampled contrast, measured hit areas and local print PDFs are concrete bounded checks, not complete WCAG or PDF accessibility certification. The sample certificates fit one A4 page; arbitrary names, browser settings and printers are not guaranteed.

Keep improvements small: knowledge should inform judgment, capability should remain bounded by actual authority, and contribution should remain voluntary and stewarded. A warm welcome is not an enrollment mechanism, and a commitment is not proof of ethical conduct.
